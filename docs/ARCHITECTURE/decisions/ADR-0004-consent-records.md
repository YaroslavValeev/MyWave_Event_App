# ADR-0004: Consent records as first-class Stage 1 entities

Дата: 2026-08-24  
Статус: accepted

## Контекст

Регистрация и публичный roster обрабатывают персональные данные. Политика (`PRIVACY_AND_CONSENT.md`) требовала `ConsentRecord`, но в коде сущности не было: регистрация не фиксировала принятие документов.

## Решение

1. Таблица `consent_records` (integer PK, как остальные Stage 1 сущности).
2. Обязательные purposes при регистрации: `terms_of_use`, `privacy_policy`.
3. Опциональные: `publish_name_and_results`, `product_analytics`.
4. Каталог версий и тексты — `docs/LEGAL/*`, отдача через публичный API.
5. Отзыв обязательных согласий запрещён, пока аккаунт используется.
6. Публичный roster маскирует ФИО self-serve заявок без `publish_name_and_results`. Импорт организатора остаётся видимым (ответственность организатора события).
7. Grant/revoke пишутся в audit.

## Последствия

- Регистрация без чекбоксов документов возвращает `consent_required`.
- Аналитический sink по-прежнему не подключён; согласие уже нельзя «включить задним числом».
- Юридическая экспертиза текстов Stage 1 не заменяет этот ADR; тексты помечены как рабочие редакции.

## Альтернативы

- Хранить согласия только в промпте/UI — отклонено (нет аудита и SoT).
- Маскировать и импортированный roster — отклонено для Stage 1: это данные организатора, не self-serve аккаунта.
