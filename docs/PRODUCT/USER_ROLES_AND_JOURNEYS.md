# Роли и пользовательские сценарии

**Дата:** 2026-08-04  
**Продукт:** MyWave Event App  

## 1. Роли

Роль всегда привязана к **событию** (Event), кроме глобальной роли `platform_admin`.

| Role code | Название | Основные возможности |
|-----------|----------|----------------------|
| `platform_admin` | Администратор платформы | Все события, пользователи, feature flags |
| `event_admin` | Организатор / админ события | CRUD события, роли, публикация, расписание |
| `judge` | Судья | Черновики и подтверждение результатов в своих категориях |
| `registrar` | Регистратор | Заявки участников, check-in |
| `athlete` | Участник | Своя заявка, расписание, свои результаты |
| `team_rep` | Представитель команды | Заявки команды, список своих атлетов |
| `commentator` | Комментатор | Read-only расширенный доступ + заметки/эфирные пометки |
| `public` | Гость | Публичные страницы без PII |

## 2. Матрица доступа (Stage 1, упрощённо)

| Действие | public | athlete | judge | event_admin | platform_admin |
|----------|--------|---------|-------|-------------|----------------|
| Смотреть публичные результаты | ✓ | ✓ | ✓ | ✓ | ✓ |
| Своя заявка | — | ✓ | — | ✓ | ✓ |
| Править расписание | — | — | — | ✓ | ✓ |
| Ввод результата (draft) | — | — | ✓ | ✓ | ✓ |
| Publish результата | — | — | ✓* | ✓ | ✓ |
| Назначение ролей | — | — | — | ✓ | ✓ |
| Удаление события | — | — | — | — | ✓ |

\* Publish судьёй — только если policy события разрешает (`judge_can_publish=true`).

## 3. Journeys (MVP-потоки)

### J1. Организатор создаёт событие

1. Входит как `event_admin` / `platform_admin`.
2. Создаёт Event (название, даты, место, видимость).
3. Назначает судей и регистраторов.
4. Публикует событие (`published`).

### J2. Участник подаёт заявку

1. Находит публичное событие.
2. Регистрируется / входит.
3. Создаёт Entry (категория, команда опционально).
4. Статус заявки: `draft` → `submitted` → `accepted` / `rejected`.

### J3. Судья фиксирует результат

1. Открывает назначенную сессию / стартовый список.
2. Вводит Result `draft`.
3. При необходимости запрашивает review организатора.
4. Публикует `published` → появляется на витрине.

### J4. Гость смотрит результаты

1. Открывает публичный URL события.
2. Видит расписание и опубликованные результаты без чувствительных данных.

### J5. Комментатор готовит эфир

1. Получает роль `commentator` на событии.
2. Читает стартовые списки и live-статусы (read-heavy).
3. Пишет внутренние заметки (не публичные без модерации).

## 4. Что не входит в Stage 1 journeys

- Оплата заявок.
- Видеопотоки / стриминг.
- Судейство полностью offline с conflict-resolution UI.
- Approve через Telegram как обязательный шаг.
