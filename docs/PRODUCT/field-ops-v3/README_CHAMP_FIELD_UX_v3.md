# Champ App — Field Operations UX v3

## Смотреть интерфейс

Откройте файл `champ_event_workflow_v3.html` двойным щелчком в Chrome/Яндекс Браузере. Интернет и сервер для просмотра не нужны. Начните с выбора роли «Организую соревнование» и пройдите «Подготовка → Судейская коллегия → Стартовые списки → Тренировочные слоты → Судейство → Протоколы → Отчёты → Результаты и грамоты». Для проверки мобильной версии включите в инструментах разработчика эмуляцию экрана шириной 393 px или откройте HTML на телефоне.

Важно: это **интерактивный UX-прототип**, не приложение и не staging. Все участники, судьи, оценки, назначения, категории и результаты вымышлены и отмечены как демонстрационные. Файлы протоколов выбираются локально, но никуда не отправляются. Нажатие «Утвердить» меняет состояние только в памяти страницы. Печать грамоты — учебный макет. Работа голосового ввода зависит от поддержки браузером SpeechRecognition, разрешения микрофона и безопасного контекста (на `file://` может быть недоступна). Выбор роли не создаёт серверных прав.

## Для разработчиков

`CHAMP_STAGE1_FIELD_UX_SPEC_v3.md` — конкретное ТЗ, привязка к текущему коду 0.5.19, 13 задач, безопасность, границы IWWF, приёмочные тесты и последовательность PR.

`test_champ_event_workflow_v3.py` — smoke tests **только для статического HTML**. Для запуска: `pip install playwright`, установить Chromium, при необходимости задать `CHROME_EXECUTABLE` и запустить `python test_champ_event_workflow_v3.py` в одной папке с HTML. В данном окружении 34/34 проверки прошли, но это не подтверждение интеграции со staging.

## Стратегия интеграции в настоящий Champ App

1. Снять Git baseline, зафиксировать бэкап данных и результаты действующих тестов.
2. Первый безопасный PR — навигация и кликабельные действия checklist в `apps/web/src/app/events/[id]/page.tsx`, новый `PreparationActionList`, исправление визуала полей и мобильного меню. Не менять API, БД и судейские расчёты.
3. Отдельно согласовать и реализовать API для категорий, назначений судей, посева и слотов. Утверждённые спортивные rule-pack версии и роль главного судьи обязательны.
4. Mobile-first судейство + запись/расшифровка комментария с явным подтверждением и контролем прав. Распознанные трюки — подсказка судье, не автоматическое официальное оценивание.
5. Протокол: камера/файл → проверка → ревизия → официальный документ. Грамоты — только из подтверждённых результатов и безопасных шаблонов.
6. Unit/integration/E2E + физический pilot dry-run. Переход в staging — только после review.

**Известный открытый вопрос:** пользователь не указал минимальную продолжительность тренировочного рана; максимум установлен как 15 минут. В коде бизнес-логики не вводить произвольный минимум.
